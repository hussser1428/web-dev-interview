GET đọc, POST tạo, PUT thay toàn bộ, PATCH sửa một phần, DELETE xoá. Safe = không đổi dữ liệu (GET, HEAD). Idempotent = gọi nhiều lần cho kết quả như một lần (GET, PUT, DELETE).
Vì sao quan trọng: client, proxy và retry logic dựa vào hai tính chất này. Request idempotent có thể tự động gửi lại khi timeout mà không sợ tạo bản ghi trùng; POST thì không.

POST /orders        # gọi 3 lần → 3 đơn hàng

Idempotency-Key: "a1b2-c3d4"   # server bỏ qua request trùng

Nhắc tới Idempotency-Key khi làm thanh toán — cho thấy bạn đã nghĩ tới retry và trùng giao dịch.

export async function auth(req, res, next) {
  const token = req.headers.authorization?.slice(7);
  const p = jwt.verify(token, SECRET);
  // cache version 60s để không query DB mỗi request
  let v = await redis.get(`tv:${p.sub}`);
  if (v === null) {
    v = (await db.user.find(p.sub)).tokenVersion;
    await redis.set(`tv:${p.sub}`, v, { EX: 60 });
  }
  if (Number(v) !== p.tv) return res.sendStatus(401);
  req.user = p;
  next();
}

Index trong database hoạt động thế nào? Khi nào index làm chậm hệ thống?

Nhận xét

Giải thích được index giúp tìm nhanh hơn nhưng chưa nói tới cấu trúc B-tree, chưa nêu chi phí khi INSERT/UPDATE và trường hợp index không được dùng (hàm trên cột, LIKE '%x').

Câu trả lời tốt hơn

Index thường là B-tree sắp xếp theo cột, giúp tìm kiếm O(log n) thay vì quét toàn bảng. Đổi lại mỗi lần ghi phải cập nhật index nên bảng ghi nhiều không nên index tràn lan. Composite index theo thứ tự cột hay lọc nhất; kiểm tra bằng EXPLAIN.
