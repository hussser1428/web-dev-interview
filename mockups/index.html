Index trong database là gì? Khi nào index làm chậm hệ thống?

Được hỏi tại: Shopee, Tiki, VNPay, +35Nguồn: github.com/…/backend-interview-questions · viblo.asia
✍ Tự trả lời trướcĐáp án gợi ýCâu hỏi follow-up (4)Thảo luận (23)

Ý chính (nói trong 30s): Index là cấu trúc dữ liệu phụ (thường là B+Tree) giúp tìm bản ghi mà không cần quét toàn bảng — đổi lại tốn bộ nhớ và làm chậm thao tác ghi.

Khi nào index làm chậm:

  • Bảng ghi nhiều (INSERT/UPDATE liên tục) → mỗi lần ghi phải cập nhật mọi index
  • Cột có cardinality thấp (vd: gender) → optimizer vẫn chọn full scan
  • Index thừa / trùng lặp, composite index sai thứ tự cột
-- Composite index: thứ tự cột quan trọng (leftmost prefix)
CREATE INDEX idx_orders_user_date ON orders(user_id, created_at);

-- ✅ dùng được index
SELECT * FROM orders WHERE user_id = 42 AND created_at > '2026-01-01';
-- ❌ không dùng được (thiếu cột đầu)
SELECT * FROM orders WHERE created_at > '2026-01-01';
💡 Mẹo ghi điểm: Kể một lần bạn dùng EXPLAIN để tối ưu query thật trong project — nhà tuyển dụng đánh giá cao trải nghiệm thực tế hơn định nghĩa.

  const key = `product:${id}`;
  const cached = await redis.get(key);
  if (cached) return JSON.parse(cached);
